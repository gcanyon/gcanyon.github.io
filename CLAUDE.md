# geoffcanyon.com — instructions for Claude Code

Geoff's personal site, hosted on GitHub Pages (custom domain in `CNAME`). It is a static site generated by `build.py`; generated HTML is committed to the repo root.

## Publishing a post
1. Create `content/posts/YYYY-MM-DD-slug.md`. Front matter between `---` lines:
   `title`, `date` (ISO), `topic` (ai | coding | product | people | games | fiction), `dek` (one or two sentences), and optional `pinned: true`, `thumb`, `hero`, `hero_caption`, `signoff`, `draft: true`.
   Posts with `legacy_url` are links to old standalone pages or external articles; they have no body.
2. Body is Markdown. `>` quote = pull quote. `![alt](/img/x.jpg "caption")` = figure with caption. `:::play Name | one line | /url` = "Play it" callout. Put images in `img/`.
3. Run `python3 build.py` (needs `pip install markdown`). Preview with `python3 build.py --serve`.
4. Run `python3 build.py --strict`; it fails if any `[bracketed placeholder]` or `needs_review` field remains. Never publish with it failing.
5. Commit the content AND the generated files (`index.html`, topic folders, `posts/`, `archive/`, `about/`, `feed.xml`, `sitemap.xml`), then push.

## Rules
- Work on the `redesign` branch until Geoff approves merging to `main`. Never force-push. Never merge or push to `main` without his OK.
- Never invent facts about Geoff's career, dates, or opinions. Use a `[bracketed placeholder]` (the checker catches it) or ask.
- Write in his voice: plain, first person, a little wry, professional. No hype.
- Site-wide details (bio, status line, topics, jobs, links) live in `site.json`; About page prose in `content/pages/about.md`.
- Don't hand-edit generated HTML; change `build.py`, `assets/site.css`, or content, then rebuild.
- Old pages (`articleswithclaude.html`, `googlevsopenai.html`, `livecodewgpt.html`, `lightyard*.html`, `international.html`) keep their URLs. Leave them alone.
- Design: light gray #F0F0EE, terracotta accent #B5502F, Fraunces / Source Serif 4 / JetBrains Mono, 700px column.
